## ระบบทำงานอย่างไร

สองโครงการต้นทางยังเป็นผู้ผลิตข้อมูล MAIAC/CAMS และ FIRMS/Emission แยกกัน โครงการนี้รับเฉพาะผลที่เผยแพร่แล้วจากแต่ละ Git commit มาตรวจสอบและจัดเก็บเป็น snapshot จากนั้นจึงเผยแพร่หน้าเว็บกลาง ไม่เรียก API NASA/ADS/FIRMS ซ้ำ ไม่คัดลอก API key หรือไฟล์โมเดล และไม่เปลี่ยนวิธีคำนวณต้นทาง

ไฟล์เว็บไซต์อยู่ใน `web/` ข้อมูลอากาศใน `web/data/air/` และข้อมูลไฟใน `web/data/fire/` รายละเอียด commit การรับข้อมูล เวลาเดิม และสถานะอยู่ใน `manifest.json` รหัสกริดสองระบบต่างกันแต่กริดจริงตรงกัน 1,052 ช่อง ตาราง `grid_crosswalk.json` เชื่อมผ่านตำแหน่ง UTM EPSG:32647 และตรวจพิกัดรูปทรงหลังตัดขอบเขต

เมนูภาพรวม ฝุ่นในอากาศ ไฟและการปล่อยฝุ่น แผนที่ข้อมูลร่วม และเกี่ยวกับข้อมูล ใช้วันที่ร่วมกัน แผนที่เปิด–ปิดชั้นฝุ่น กริดไฟ จุดความร้อน เส้นกริด และเชื้อเพลิงได้ คลิกกริดเพื่อดูข้อมูลสองระบบ พร้อมดาวน์โหลด CSV แยกหน่วยและเวลา

## ค่าเริ่มต้นและการเลือกข้อมูล

- หน้าแรกเปิดวันไทยปัจจุบัน ใช้ MAIAC ก่อนถ้ามีค่าจริง มิฉะนั้นใช้ CAMS
- เมนูมีเฉพาะ MAIAC/CAMS สลับแหล่งเองแล้วคงวันที่เดิม เมื่อเลือกวันใหม่ระบบเลือกแหล่งตามข้อมูลของวันนั้นอีกครั้ง
- CAMS ของวันนี้/อนาคตเลือกชั่วโมงที่ใกล้ปัจจุบันที่สุดภายในวันที่เลือก วันที่เก่าใช้ค่าเฉลี่ยรายวัน ปุ่มใกล้เวลาปัจจุบันจะกลับสู่ชั่วโมงพยากรณ์ที่ใกล้ตอนนี้ที่สุด
- MAIAC แสดง IDW กำลัง2 ใกล้ที่สุดไม่เกิน12จุด ระยะทาง UTM ต้องมี3จุดไม่เรียงเส้นตรง ถ้าทำไม่ได้จะแสดงเฉพาะกริดที่มีข้อมูลพร้อมระบุว่าค่าเฉลี่ยครอบคลุมบางส่วน
- PM₁ = 0.80 × PM₂.₅ − 0.71 และ PM₀.₁ = 0.14 × PM₂.₅ − 0.40 ที่มา (CALLAB) ตามข้อมูลผู้จัดทำ ค่าติดลบเป็น NoData ไม่แทนศูนย์
- สี PM₂.₅ แบ่งที่15/25/37.5/75, PM₁ ที่12/20/30/60, PM₀.₁ ที่2.25/3.75/5.63/11.25 µg/m³ รหัสสี PM₁/PM₀.₁ เป็นเบื้องต้น ไม่ใช้ตัดสินผลกระทบสุขภาพ 80%/15% ใช้กำหนดช่วงสี ไม่เปลี่ยนสัมประสิทธิ์0.14
- FIRMS เลือกดาวเทียม กลุ่มกริด/กริดรายช่อง และเปิด–ปิดสถานการณ์ดินพรุ0–10ซม. โดยใช้ผลเดิมของต้นทาง

## ข้อจำกัดในการอ่านร่วมกัน

ความเข้มข้นฝุ่น µg/m³ ต่างจากปริมาณการปล่อย kg ต่อวันที่เลือก ห้ามบวกหรือแปลงเป็นกันโดยตรง MAIAC ใช้วันผลิตภัณฑ์ UTC ข้อมูลไฟและ CAMSรายวันใช้วันไทย การเปรียบเทียบป้ายวันที่เดียวกันเป็นการสำรวจ ไม่ใช่การยืนยันว่ามีช่วง24ชั่วโมงเดียวกันหรือยืนยันเหตุและผล

CAMS มีความละเอียดต้นทาง0.4° แม้แสดงตัดตามขอบเขตศึกษา การประมาณ PM₂.₅ จาก CAMS AOD550 ยังใช้ Extra Trees เดิมที่ฝึกกับ AOD470 ผลยังไม่ได้สอบเทียบสถานี ไม่ใช่ PM₂.₅ พยากรณ์โดยตรงจาก CAMS

Emission เป็นสถานการณ์สมมติเผาเต็มส่วนกริดที่อยู่ในขอบเขต จุดความร้อนเป็นศูนย์กลางตรวจพบ ไม่ใช่รูปทรงพื้นที่เผายืนยัน ค่าใช้พื้นที่×ρ×η×EF ชั้นเชื้อเพลิงที่ทับซ้อนคงทับซ้อน รายวันอิสระไม่หักเชื้อเพลิงจากวันก่อน และไม่ใช้ผลรวมหลายวันเป็นพื้นที่ไฟที่ไม่ซ้ำ

สถานะรับsnapshotสำเร็จไม่ได้หมายถึงทุกดาวเทียมมีข้อมูลครบ ต้องดู `observation_state` และสถานะแยกแหล่งด้วย ค่าศูนย์ในชุดบางส่วนหมายถึงไม่พบในข้อมูลที่ได้รับ วันที่วันนี้ยังอาจไม่ครบวัน

## อัปเดตอัตโนมัติ

Workflow `.github/workflows/platform.yml` รับข้อมูลจากสองคลังทุกชั่วโมงที่นาที17และ47 (ทุกประมาณ30นาที; GitHubอาจเริ่มช้าตามคิว) และเมื่อpushโค้ดหรือสั่งรันเอง ระบบอัปเดตได้แม้ปิดคอม ข้อมูลใหม่ขึ้นกับรอบและความพร้อมของต้นทาง ไม่มีการสร้างงานAutomationในแชต

ใช้เฉพาะ `GITHUB_TOKEN` ที่ GitHubสร้างให้ขณะรัน เพื่ออ่านข้อมูลสาธารณะและบันทึกsnapshot ไม่ต้องเพิ่ม NASA/CAMS/FIRMS secrets ในคลังนี้ ไฟล์ที่ไม่เปลี่ยนไม่ดาวน์โหลดซ้ำ แต่ละชุดตรวจทั้งชุดก่อนแทนของเก่า ถ้าแหล่งหนึ่งล้มเหลวจะรักษาชุดก่อนพร้อมสถานะstaleและเวลาเดิม หากยังไม่มีชุดที่จำเป็นตั้งแต่ต้นจะไม่เผยแพร่เว็บที่ไม่มีข้อมูล

## พัฒนาและทดสอบ

Python3.12 และ Node22 ไม่ต้องติดตั้งแพ็กเกจเพิ่มเติมสำหรับรับข้อมูลหรือทดสอบ:

```powershell
cd 'D:\LAB website\kuan-kreng-monitoring-platform'
python scripts/sync_data.py
python -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/model.test.cjs
node --check web/app.js
python -m http.server 8770 --bind 127.0.0.1 --directory web
```

เปิด `http://127.0.0.1:8770/` วิธีรับข้อมูลแบบofflineจากสำเนาท้องถิ่นและรายละเอียด schema ดู `docs/DATA_CONTRACT.md` ใช้สำหรับพัฒนาเท่านั้น การเผยแพร่จริงรับจาก upstream GitHubที่ pin commit
